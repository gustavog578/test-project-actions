# Documento Técnico - Deploy

1. **Resumen Ejecutivo**
   Se ha implementado una nueva funcionalidad para listar a los usuarios del sistema desde una nueva vista `/users.html`, accesible desde el dashboard mediante un botón. Además, se agregó la opción de ver la contraseña de cada usuario en un modal popup que inicialmente aparece oculto.

2. **Cambios Backend (express)**
   Se añadió una nueva ruta en el servidor para obtener la lista de usuarios solo si el usuario está autenticado.

   ```javascript
   app.get('/api/users', (req, res) => {
       if (req.session.loggedIn) {
           res.json(getUsers());
       } else {
           res.status(401).json({ error: 'Unauthorized' });
       }
   });
   ```

3. **Cambios Frontend (carpeta /public)**
   - Se añadió el archivo `users.html` para la nueva página de gestión de usuarios.
   - Se creó `users.js` para la lógica de mostrar usuarios y gestionar el modal de contraseñas.
   - Se modificó el `dashboard.html` para incluir un botón de navegación hacia `users.html`.

   ```html
   <!-- dashboard.html -->
   <div style="display: flex; gap: 10px;">
       <button class="logout-btn" style="background-color: #2196F3; border-color: #2196F3;"
           onclick="window.location.href='/users.html'">Ver Usuarios</button>
       <button id="logoutBtn" class="logout-btn">Logout</button>
   </div>
   ```

   ```html
   <!-- users.html -->
   <table class="users-table">
       <thead>
           <tr>
               <th>Usuario</th>
               <th>Acción</th>
           </tr>
       </thead>
       <tbody id="usersTableBody">
           <!-- Users will be populated here by users.js -->
       </tbody>
   </table>
   ```

4. **Impacto Técnico**
   - Se amplia la capacidad del sistema para gestionar usuarios directamente desde la interfaz, mejorando la usabilidad.
   - La nueva funcionalidad requiere asegurar que los modales siempre estén correctamente sincronizados con la información mostrada.

5. **Riesgos**
   - Mostrar contraseñas, incluso temporalmente y a usuarios autenticados, puede ser considerado un riesgo de seguridad.
   - Error en el control de sesión puede permitir acceso no autorizado al listado de usuarios.

6. **Consideraciones de Deploy**
   - Asegúrese de que las sesiones estén correctamente configuradas en el servidor.
   - Verificar que el cliente pueda manejar el cierre de sesión correctamente.
   - Implementar controles adicionales para garantizar la seguridad de las contraseñas.
