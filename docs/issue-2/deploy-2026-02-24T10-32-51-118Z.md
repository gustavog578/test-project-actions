# Documento Técnico - Deploy

1. **Resumen Ejecutivo**  
   El objetivo principal del Issue #2 es añadir una funcionalidad que permita listar los usuarios del sistema y visualizar sus contraseñas. Para lograr esto, se ha creado una nueva ruta `/users` y se ha añadido un botón en el dashboard para acceder a dicha lista. Las contraseñas están inicialmente ocultas y se muestran al usuario en un popup tras presionar el botón "ver contraseña".

2. **Cambios Backend (express)**  
   No se realizaron cambios específicos en el backend o en la lógica del servidor (archivo `server.js`). Los cambios mencionados se centran principalmente en la lógica de frontend y la interacción de usuario.

3. **Cambios Frontend (carpeta /public)**  
   Se realizaron modificaciones en el archivo `scripts/capture-screens.js`, donde se realizaron importantes ajustes para capturar automáticamente pantallas que muestran la funcionalidad añadida.  
   - Se añadió lógica para definir qué rutas capturar con base en el issue actual.
   - Se mejoró el enfoque del prompt de IA para priorizar interacciones que revelen la funcionalidad de ver contraseñas.
   - Se registraron acciones de IA y se tomaron capturas de pantalla tras la interacción.

4. **Impacto Técnico**  
   La implementación proporciona un mecanismo automatizado para verificar, de forma visual, las funcionalidades de visualización de contraseñas en los usuarios listados. Esto puede facilitar el aseguramiento de la calidad al validar automáticamente el comportamiento esperado a través de capturas de pantalla.

5. **Riesgos**  
   - Si hay cambios futuros en la estructura del HTML o en los identificadores de los elementos interactivos (como botones), el script de captura de pantalla puede fallar al no encontrar los elementos esperados.
   - El mostrar contraseñas, incluso de manera temporal, puede presentar un riesgo de seguridad si no se controla adecuadamente a quién se le otorga acceso a esta funcionalidad.

6. **Consideraciones de Deploy**  
   Se debe asegurar que el servidor Express esté configurado de manera adecuada para servir correctamente los archivos de la carpeta `/public` y que las rutas necesarias, especialmente `/users`, estén disponibles y sean funcionales en el entorno de producción.
