Manual de Usuario: Pipeline de Documentación Automatizada

Este sistema transforma el proceso de documentación técnica en un flujo pasivo y automatizado, asegurando que cada cambio visual en el producto quede registrado sin intervención humana directa.

1. Las 3 Piezas del Motor

El sistema operando en GitHub Actions ejecuta tres procesos críticos:

  • Captura (Playwright + IA): Emula a un usuario, navega por las rutas afectadas y realiza acciones dinámicas (clicks, selección de menús) para revelar la funcionalidad oculta.
  • Redacción (OpenAI GPT-4o): Interpreta el código fuente y el contexto humano del ticket para escribir un informe técnico de alta calidad.
  • Persistencia: Guarda los hallazgos en carpetas organizadas por Issue ID para mantener el orden histórico.

💡 Flujo Diario para Desarrolladores

  1. Commits con Contexto: Incluye siempre el #ID de la issue en tu mensaje de commit.
  2. Sincronización Previa: Antes de trabajar, haz un git pull --rebase origin main. Esto es vital porque el bot genera commits automáticos de documentación.
  3. Validación: Revisa la carpeta /docs después de cada push exitoso para validar la evidencia.

2. Organización de Archivos

La estructura de carpetas está diseñada para la escalabilidad:

/docs
  /issue-2
    /images
      dashboard-action-174000.png  <-- Fotos del ticket 2
    deploy-2026-02-24.md           <-- Doc del ticket 2
  /general
    /images                        <-- Fotos sin ticket asociado
    deploy-info.md                 <-- Doc general

⚠️ ¡Atención con los Conflictos!

Como el sistema es un "miembro más" del equipo que hace commits en main, si olvidas hacer rebase, podrías tener conflictos de Git al intentar subir tu código. Si esto sucede, resuelve el conflicto favoreciendo tus cambios de código sobre los documentos del bot, y vuelve a pushear.

3. Configuración de Seguridad (Github Secrets)

Para que el sistema respire, necesita:

  • OPENAI_API_KEY: Token de acceso a la API de OpenAI.
  • GITHUB_TOKEN: Permisos de lectura de Issues y escritura de contenido (configurado en el archivo YAML).
